# MobaBot.io 0.12 — Combat Foundations

## Implemented

- Two independent attack systems. Autonomous gun ignores S, movement, target orders and channels. Commanded basic attacks use their own cooldown; right-click enemy approaches and attacks, ground click cancels that order, S stops walking/basic attacks. Existing powered-passive energy depletion still switches powered tools off.
- A then left-click shows basic range and attack-moves. It selects the closest-to-cursor enemy among in-range targets, reacquires after death and resumes movement when none remain. Target orders approach/hold/rechase without boundary oscillation in the stationary-target test. Esc, skill selection and modal opening cancel A targeting.
- Immediate starting gun and Q. Slot 1 cycles machine gun → sniper → off → machine gun. Old custom loadouts are normalized in memory; Orbit/Ricochet dependency survives. Saved source dictionaries are not mutated by normalization. No redundant ten-second gun-unlock announcement.
- Coolant trail selectable in passive slots 2–4: 3 energy/sec while on, no upkeep off, no self-damage, 4s patches, 8 base DPS scaling with Weapon power, nonstacking coverage, capped patch count. Existing laid patches expire after switching off. One new native vial icon and reduced-effects-compatible coverage rendering.
- One mastery point per Power level in live runs; current nine-node tree remains. Main-menu preview stays read-only. Equipment remains persistent and unchanged; no save conversion or reset.
- Separate basic/auto firing numbers in stats and upgrade previews, source labels in damage summary, machine/sniper/off HUD states, attack controls in Settings and A reserved during rebinding. Q remains visually distinct from small automatic projectiles.
- Version/title/README/agent handoff updated. Added reproducible tests and current-mode options to both behavior probes.

The policies buy upgrades/rewards and the adaptive policies spend mastery; even the policy named idle is not literally zero UI input.

## Evaluation / remaining work

The new controls provide a testable distinction between passive spectacle and deliberate attacks. Combined DPS and extra tree points materially change balance; the prior 0.11 balance numbers no longer apply. Three seeds are too few for difficulty certification. One idle seed surviving into round two is an opening-pressure warning. Do not call the combat tuned or the boss fair based on these probes alone. The small tree can exhaust meaningful purchases before an expanded run ends.

The eight-stage route, class selection, chest discovery/duplicate +2 ranks, shop rounds, ascensions, larger tree, eight equipment slots and forty-item set art are **not implemented**. The design artifact maps every note to existing primitives, proposed adaptations or unresolved meanings: [systems refinement and roadmap](SYSTEMS_REFINEMENT_12.md). D/F, pet availability and later timed unlocks still reflect the old demo and are explicitly temporary.

Next implementation milestone: central higher-resolution stats/source tags and chest-driven discovery in Stage 1. Then representative ranged/melee/summon skills, expanded tree, versioned equipment conversion, data-driven route/shops and ascension tuning. Preserve existing gear and saves throughout. Chosen direction is persistent equipment collection/upgrades with run-only abilities/tree allocations; the new eight-slot economy has not been migrated into live saves.

No blocker prevents testing 0.12. Snowball, bastion heal and drop SFX potency remain parked clarification questions; Shunpo is removed, poison trail interpretation is confirmed. Obstacle vaults/walls need a navigation system before implementation. Public release still needs packaging, lower-end performance, audio listening, music rights confirmation and human playtesting.
