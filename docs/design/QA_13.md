# 0.13 — Minimal UI

## What remains

The creator asked for aggressive subtraction before adding more interface. This is a menu/presentation pass, not a combat or progression revision.

| Surface | MVP version |
| --- | --- |
| Home | Play, Loadout, Equipment, Settings, Quit |
| Tab / Build | Overview and Mastery |
| Overview | Equipped ability/passive/gear icons; six core stat rows; credits |
| Loadout | Abilities and Passives |
| Settings | Options and Controls |
| Options | Sound, Reduced effects, Camera lock, Area quick cast |
| Controls | Essential fixed inputs and eleven rebindable ability slots |
| Equipment | Equipped slots, item collection, one selected comparison and its actions |

## Removed or moved

- Removed home mastery preview, decorative three-encounter itinerary, subtitle and repeated demo wording. Existing foundry art remains.
- Removed separate Stats, Upgrades, Abilities and Gear navigation from Build. Overview replaces those pages; the nine-node mastery tree and purchases remain.
- Removed the visible damage-source dashboard and twelve-stat layout. Six rows remain: hull, energy, ability damage, auto fire rate, movement speed and pickup reach. Energy balance, basic/auto damage and secondary bonuses live in inspection details. No combat stats were deleted from the simulation.
- Removed Utility and Keys tabs from Loadout. Magnet is still free utility and still appears as pickup reach/mastery. Bindings now belong to Settings → Controls, accessible from home or a paused run; edits still apply next run, explicitly labeled.
- Removed the settings zoom slider and six-line instruction block. Wheel zoom remains; control reference is grouped on its own page. Retained reduced effects rather than pruning accessibility-related functionality.
- Removed decorative equipment robot schematic, repeated ownership words, fitted-status repeats and duplicate star/spare readouts. Kept item counts, stars in the inspector, base/bonus distinction, signed comparisons, action costs, disabled purchases and save failures.
- Removed cooldown/charge metadata from loadout tiles; it remains on hover. Kept icons, names and energy costs. Removed zero-rank numbers from the overview.
- Removed the running kill counter; it remains in results. Results show credits instead of the less actionable scrap count. Removed unsolicited death-advice sentence; final-hit cause remains.
- Simplified the focus-loss pause menu to Resume, Settings, Main menu. In-run Settings now has an exit with a leave-run confirmation, so the main menu does not depend on losing application focus.

Normal navigation does not offer an Advanced page or another directory of removed screens. Historical inspection renderers are retained only for fixtures/source reuse. They are not newly shipped user-facing features. Core upgrade cards still show current-to-next numerical benefits; mastery still has its selected-node inspector. Those are necessary choices, not decorative dashboards.

## Interaction and evidence

Consistent Back placement, predictable focus and grouping by task follow Microsoft's UI navigation guidance. This is an application of those principles, not a claim of complete accessibility certification. [Xbox Accessibility Guideline 112](https://learn.microsoft.com/en-us/xbox/accessibility/xbox-accessibility-guidelines/112).

Vampire Survivors pause screenshots show current-run stats and equipment inspection together, with a small navigation row. We borrowed that compact inspection pattern, not the full dense list of modifiers. [Referenced pause-screen screenshot and context](https://gameriv.com/how-to-unlock-use-milky-way-map-in-vampire-survivors/). League's official discussion treats remapping as part of game options; this supports keeping controls in Settings rather than in the ability-selection menu. We did not import its newer movement schemes or full options surface. [Riot: input customization](https://www.leagueoflegends.com/en-ph/news/dev/dev-wasds-ranked-release/).

Our choice is intentionally smaller than mature games' menus. Their years of options/content are not an MVP requirement. No reference art was downloaded or copied.

Overview details are available through hover or click/keyboard activation. The selected detail renders inside the existing game canvas, with a Back button and trapped directional focus. Esc closes the detail before the Build screen; releasing held Tab still returns to the prior screen. Settings toggles preserve focus across redraws. Reserved-key errors stay visible, and Esc cancels rebinding before exiting Settings. Rebinding cannot issue a movement/ability command to the paused run.

## QA and handoff

Godot 4.7.2 / Windows. Final full regression: **1,830 checks, zero failures**, including **35 new menu tests**. Layout audit includes the new overview/controls screens and retained historical rank previews. Final log and render logs were scanned for script errors, not merely process exit codes: Godot can return success despite script compilation errors.

New tests cover exact home action count, four preferences, removed routes, all bindings, reserved-key rejection, reset/cancel behavior, focus retention, six core stat rows, active inspection, detail focus isolation, Esc ordering, mastery purchase, leave confirmation and returning to the same run. Earlier tests still verify progression, combat, movement, equipment and persistence validation. A teardown timing warning in the older salvage UI test was addressed by explicitly stopping audio and allowing it to retire before exit.

Rendered 1600×900 home, options, controls, equipment and overview were inspected; the final home/controls/detail layouts were also checked at 1280×720. Initial detail-popup capture did not render as part of the main canvas; it was replaced with the verified in-canvas panel. No listening claim: visual QA uses Dummy audio. No permanent rewards or purchases were saved by tests.

This establishes no measured combat change in those policies, not human difficulty or fun.
